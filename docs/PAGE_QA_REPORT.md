## 浏览器实抓范围

使用 Chromium 打开 `src/pages.json` 注册的全部 29 个页面，并按普通用户、救援志愿者和平台审核员三种身份重复检查角色相关入口，共形成 35 个页面/角色场景。每个场景分别以 `390 × 844` 移动视口和 `1440 × 1000` 桌面浏览器复核；桌面端内容固定为居中的 430px 手机视口。

另外，对首页、健康、个人中心、设备、体检、科普及三种角色专属入口执行 28 条真实点击跳转，包含志愿者任务到救援详情；源码中的全部模板点击绑定执行处理函数存在性与目标路由注册校验。删除、拨号、正式 SOS 和审核写操作不在自动化中真实提交，避免污染数据。

检查项包括：

- 页面可访问且主体内容非空；
- 页面标题与业务场景一致；
- 无未登录回退、空白页或异常中断；
- 同源 API 无 4xx/5xx；
- 浏览器控制台无错误；
- 页面无横向溢出；
- 移动浏览器使用真实全宽，桌面浏览器使用单层 430px 手机预览；两者均不存在嵌套纵向滚动；
- 桌面浏览器保持 430px 手机视口，固定导航、地图、抽屉、弹层和悬浮操作不得跑出手机边界；
- 用户界面无 Spring AI、OCR、服务端等实现词和原始枚举值；
- 所有非 Tab 注册页面均有真实业务入口，不保留不可达页面；
- 首屏主任务和关键操作未被裁切；
- 地图、ETA、双方联络、AED 交接、现场处置与完成确认的层级清晰。
- 途中显示路线与 ETA；到达后地图实例销毁并切换到现场处置界面，不再显示无意义的现场导航。
- 途中路线卡统一承载 AED、目的地、ETA 与距离，不再重复渲染 AED 资料卡、地图内导航按钮或第二个 120 入口；专项内容审计全部通过。
- 后台定位失败不会自动弹出选点页，也不会阻断志愿者任务加载；手动选点只由用户主动操作触发。
- SOS 首屏为完整医疗红背景，提交后进入独立匹配反馈态；不出现同心圆、伪路线或出行平台式接单文案。
- 三个身份门户及全部页面统一为 Apple 平台语言：浅色导航、系统灰画布、白色分组行、44pt 触控区和语义色。
- 救援记录、设备管理、联系人、设置和审核使用成组列表，减少重复悬浮卡、装饰渐变与无意义线条。
