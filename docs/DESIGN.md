# 脉安驰援设计规范

## 1. 设计目标

脉安驰援服务两种截然不同的状态：

- 日常状态：用户查看健康数据、管理设备、学习急救知识，需要平静、清晰和可信。
- 紧急状态：用户可能焦虑、单手操作或替他人呼救，需要最短路径、强反馈和低误触。

界面整体应像一台安静可靠的医疗仪器。红色只在呼救、危险和高风险状态出现，不能成为装饰色。

## 2. 领域语言

- AED 机柜
- 救援路线
- 心电波形
- 手环传感器
- 体检档案
- 响应者信标
- 救援时间轴

项目的标志性视觉元素是“生命线”：用连续脉冲线连接呼救、匹配、响应、抵达和完成状态。

## 3. 色彩系统

| Token | 色值 | 用途 |
|---|---|---|
| `rescue-blue` | `#2E6DD1` | 品牌、主操作、链接 |
| `rescue-blue-soft` | `#EAF2FC` | 图标底色、选中背景 |
| `signal-red` | `#C93D46` | SOS、危险、高风险 |
| `signal-red-soft` | `#F9EAEC` | 危险提示背景 |
| `monitor-green` | `#23956A` | 正常、在线、可用 |
| `warning-amber` | `#C98327` | 维护、提醒、待确认 |
| `instrument-ink` | `#20364D` | 主文字 |
| `slate` | `#728296` | 次级文字 |
| `muted` | `#9AA8B7` | 辅助信息、占位 |
| `canvas` | `#F3F7FA` | 页面背景 |
| `surface` | `#FFFFFF` | 内容表面 |
| `line` | `#E1E9F0` | 分割线、边框 |

规则：

- 品牌交互只使用医疗蓝。
- 红色绝不用于普通快捷入口或装饰渐变。
- 正常、警告、危险必须同时使用文字或图标表达，不能只靠颜色。

## 4. 字体与数字

- 中文：系统无衬线字体，优先使用设备原生字体。
- 页面标题：40rpx / 700。
- 区块标题：32rpx / 700。
- 正文：28rpx / 400–500。
- 辅助文字：22–24rpx / 400–500。
- 健康数值、距离和时间使用等宽数字：`font-variant-numeric: tabular-nums`。

## 5. 间距与形状

- 基础单位：8rpx。
- 常用间距：8 / 16 / 24 / 32 / 48rpx。
- 小控件圆角：12rpx。
- 按钮圆角：16rpx。
- 卡片圆角：24rpx。
- 弹层圆角：32rpx。
- 深度策略：浅边框加单层轻阴影，不使用多层重阴影。

圆角卡片与胶囊控件不是禁用元素，但必须承担明确的信息分组或状态选择作用。相邻卡片要通过尺寸、留白、材质和操作权重形成层级，不能把所有内容做成相同大小、相同阴影的模板块。

## 6. 图标规范

- 通用操作使用 `uni-icons`，保证 uni-app 多端一致性。
- 医疗专用图标使用 Health Icons 的 outline 风格。
- 图标默认线宽保持统一；同一区域禁止混用填充、线性和 Emoji。
- 独立图标放入浅色方形容器；与文字同行的图标不添加无意义底色。
- AED 保留 `AED` 文字识别，避免使用含义模糊的心形或闪电符号代替。

禁止：

- 使用 Emoji 充当搜索、位置、电话、档案、车辆、医生等功能图标。
- 用首字母或随意字符模拟设备品牌图标。
- 为每个入口分配一种装饰色。

## 7. 组件状态

每个交互组件必须具备：

- 默认
- 按下
- 禁用
- 加载
- 错误

列表和数据区域必须具备：

- 骨架加载
- 空状态
- 请求失败及重试
- 数据更新时间

面向用户的状态必须经过统一呈现层转换：未知状态显示“状态更新中”，外部服务或程序异常显示可执行的恢复建议。禁止直接展示 `SYSTEM_FAILED`、异常类名、接口地址、模型名称、框架名称和服务端实现方式。

## 8. 页面优先级

1. 首页：紧急入口、附近设备、健康状态。
2. 呼救页：防误触、定位、症状、现场图片、提交反馈。
3. 救援详情：生命线时间轴、途中位置、到场处置、沟通与完成确认。
4. 急救地图：固定/移动设备差异、筛选、路线。
5. 健康页：实时数据、趋势、告警。
6. 体检报告：原图上传、人工指标录入、规则分析。
7. 科普与个人中心。

## 9. 层级与动效

救援页面采用三层结构，不能把全部信息处理成相同白卡：

1. 状态层：生命状态、紧急程度和主时间轴，使用低饱和环境光建立最高视觉层级。
2. 驰援层：仅在赶往 AED 或求救现场途中展示地图、AED 光轨、ETA 与剩余距离；到场后退出地图语境。
3. 处置层：当前唯一主操作、双方协同、设备与现场资料。

动效参数与场景：

- 快速反馈 `140ms`：按钮按压、开关和图标响应。
- 列表入口使用 `280ms` 溶解，首批内容以小幅错峰落位建立阅读顺序。
- 表单与创建流程使用 `440ms` 自底部轻柔上浮，表达临时任务面板关系。
- 详情和报告使用 `380ms` 聚焦进入，以轻微缩放和纵向位移建立上下文，不使用生硬横向滑入。
- 同页分段切换只替换内容区域，使用 `300–320ms` 局部交叉过渡，不让导航和页面框架重复进场。
- 内容进入 `360ms`：主要区块按 `45ms` 间隔错峰出现。
- 主按钮按压缩放到 `0.98`，同时保留颜色和阴影过渡。
- 数据加载使用与最终布局一致的骨架屏，禁止整页空白或只有居中转圈。
- 弹层从操作来源方向进入，避免无方向的突然出现。
- 系统开启“减少动态效果”时，关闭循环动画并把过渡压缩为瞬时完成。

驰援轨迹规则：

- 正式环境只使用施救者或移动 AED 的真实定位更新路线、剩余距离和 ETA。
- Demo Mode 可以沿建议轨迹模拟 AED 行进，用于展示路线流动、信标移动、ETA 和距离联动。
- 路径流光、AED 呼吸信标和数字变化必须同步，不能只是互不相关的装饰动画。
- 已到场后停止行进模拟并销毁地图，界面切换为“已到达救援现场”的处置态；不得在地图上继续显示“已到达”或提供现场导航。
- 呼救提交后必须先展示可感知的匹配状态；匹配动画表达呼救送达、附近响应与 AED 协同，不使用静止同心圆冒充动态反馈。

紧急呼救视觉规则：

- 呼救入口使用完整的医疗红背景形成唯一的紧急语义，不再套白色主卡、雷达圆环或出行平台式接单面板。
- 首屏只保留 SOS、用途说明、已确认位置、发出呼救和拨打 120；现场资料默认折叠，避免危急时阅读负担。
- 发送后的等待态延续全红背景，通过节奏点和阶段进度反馈系统正在工作，不虚构已经匹配成功、路线或到达信息。
- 除紧急呼救外，全部页面采用浅灰画布、浅色导航、深色标题与白色分组内容，三个身份门户共享同一套 Apple 平台语言。

Apple 平台语言基线：

- 导航与底栏属于功能层，可使用克制的半透明和模糊；内容卡、表单和列表使用不透明标准材质，不在内容层滥用玻璃效果。
- 文本型内容优先使用 iOS 分组列表：组内以行和细分隔线组织，组间靠标题与留白区分；避免“一条数据一张悬浮卡”。
- 主操作、表单按钮和高频触控区域按不小于 44pt 设计；相邻控制保留足够间距，危险操作使用医疗红并与普通操作分离。
- 使用系统字体与系统化字号层级，支持文字放大后自然换行；列表标题保持简短，详细说明进入下一层页面展示。
- 色彩只表达交互和状态：系统蓝用于操作，生命绿用于在线/完成，医疗红用于危险/呼救，琥珀用于待处理；禁止装饰性渐变和随机彩色头像。
- 动画采用 150–260ms 的按压、淡入和局部状态变化；避免弹跳、快速闪烁和大幅横向滑动，并响应系统“减少动态效果”。

信息密度规则：

- 列表优先采用分组行与分隔线，不为每条数据重复创建大面积悬浮白卡。
- 技术实现、完整 UUID 和内部错误枚举不属于用户决策信息，不在界面展示。
- 减少文案后必须用主视觉、材质、状态色与空间层级维持辨识度，不能退化成无重点的后台表单。
- H5 在移动浏览器使用真实全宽，在桌面浏览器居中显示 430px 手机视口；手机视口只约束宽度，不持有第二个滚动容器。每页只能有一个纵向滚动主体，滚动条不作为界面装饰出现。
