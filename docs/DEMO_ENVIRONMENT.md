# 本机测试与比赛演示环境

该环境启动真实 Spring Boot 后端、H5 前端和后台 Agent 调度器。数据单独保存在 `.cache/preview/`，使用 H2 的 MySQL 兼容模式；不连接 MySQL、不执行 Flyway，不验证生产迁移。演示启动器位于 `scripts/`，不会打入生产后端 JAR。

## 启动与停止

在仓库根目录运行：

```bash
npm run dev:preview
```

首次启动下载 Java 21 JDK 和 Maven 到 `.cache/preview/tools/`，安装缺失的前端依赖并构建后端。自动下载适用于 Linux x86_64，需要 Node.js、npm、Python 3、curl、tar 和外网。脚本优先使用缓存离线构建；未命中缓存再联网。其他平台可将 Java 21 JDK 放在 `.cache/preview/tools/jdk/`。

已有与当前代码一致的后端构建产物时，可以快速启动：

```bash
npm run dev:preview -- --skip-build
```

访问 <http://localhost:5173/maian/>。前后端只监听本机，端口分别为 5173 和 8080；端口已占用会拒绝启动。保持启动终端运行，按 `Ctrl+C` 停止前后端。日志分别位于 `.cache/preview/logs/frontend.log` 和 `backend.log`。

本环境强制前端请求走本地代理，忽略已有环境中的后端地址与首次管理员初始化参数。OCR 默认关闭；在仓库根目录的 `.env` 设置 `BAIDU_OCR_ENABLED=true`、`BAIDU_OCR_API_KEY` 和 `BAIDU_OCR_SECRET_KEY` 后，重启预览即可启用。启动器仅向后端进程加载这些凭据，实际密钥保存在被 Git 忽略的 `.env`，示例文件只保留空值。识别检查单前仍需用户授权健康数据处理。

高德 JavaScript API 使用同一个 `.env` 中的 `VITE_AMAP_KEY` 和 `VITE_AMAP_SECURITY_CODE`，分别填写 Web 端 Key 与配套安全密钥，重启前端后启用 POI 搜索与道路路线规划。栅格底图仍沿用原实现。

未配置模型时使用站内指令；若存在 `.cache/preview/ai-key`，启动器仅在后端读取该密钥并启用模型，模型名称读取 `.cache/preview/ai-model`（默认 `deepseek-flash`）。这些本地文件不提交Git，不进入前端构建产物。当前实验环境已连接DeepSeek，实际执行模式保留在接口结果中。

## 测试账号与样例

| 角色 | 手机号 | 用途 |
| --- | --- | --- |
| 普通用户 | 19900000001 | 查看救援记录、生成复盘、评价、管理设备、使用助手 |
| 急救志愿者 | 19900000002 | 查看已参与的任务、归还固定 AED |
| 管理员 | 19900000003 | 设备审核、投稿审核、账户权限 |

初始共用密码：`MaianDemo2026!`，保存在 `.cache/preview/password`。首次启动前设置 `PREVIEW_PASSWORD` 可指定其他 12～72 位密码；已有数据库重启不会修改密码。JWT 密钥首次随机生成并保存在本地，账号和密钥文件不会提交 Git。

演示登录页列出三个角色的账号，点击自动填入手机号和当前演示密码，并滚动回登录表单；点击「登录」后才发送登录请求。注册模式隐藏快捷账号。入口仅在预览启动器提供演示密码时显示，正式构建不包含该密码。

首次初始化在一个事务中创建以下虚构数据，重启复用当前数据，不覆盖演示操作：

- 一条已完成的救援，含十条事件、真实领域状态流转、待归还 AED 和待评价状态，尚未生成复盘。
- 一条已取消的救援，用于检查没有接单、到场时间时显示“未记录”。
- 五台固定 AED：待归还、两台可用备选、待审核、故障维护。
- 一条设备故障协同任务，交给实际后台调度器处理并保存工具过程。
- 三篇已审核的演示文章和一篇待审核投稿，用于检索、推荐和审核流程。

设备、地址、时间和文章均标有演示语义。文章内容用于验证功能入口，不代表真实医学资料；坐标为固定的杭州示例位置。新建现场救援时，双方位置与 AED 必须在调度半径内，可在地图选点后演示。样例 ID 保存在 `.cache/preview/demo.json`，启动后会打印已完成救援的直接访问地址。

## 推荐体验顺序

需要更充实的场景数据时，在预览环境运行后执行：

```bash
python3 scripts/seed-preview-data.py
```

脚本仅连接当前仓库的 H2 预览库，写入前创建在线备份，整批写入使用同一事务；重复执行不追加数据，也不覆盖后续演示操作。新增 12 台不同开放时段和状态的 AED、8 条历史救援（6 条完成并归还、2 条取消）、10 篇文章和 2 篇待审核投稿、3 份体检报告、近 30 天心率与联系人。故障设备的两条协同任务交由现有后台调度器实际执行，不伪造模型执行过程。

以上数据均为虚构的本机场景素材，位置集中在原杭州示例坐标附近，不代表经过核验的现实 AED 点位或真实健康记录。界面不添加模拟标记；来源、写入数量、救援 ID 和备份位置记录在 `.cache/preview/scenario-data.json`。首次填充时将初始样例的默认名称改为自然的业务名称，仅匹配已知默认值，用户修改过的名称保留。原有业务记录和账号设置保留，不创建正在呼救的任务，也不修改数据处理授权。不要将这些场景素材导入实际业务数据库。

通过预览启动器运行时，前端定位统一使用杭州的 GCJ-02 坐标 `120.1505, 30.2805`，地图、附近距离、设备登记与助手定位指令共用该点，不请求浏览器 GPS。仅在开发服务器启用预览账号配置时生效；正式构建将该配置设为 `null`，继续使用真实定位。周边场景设备由上述填充脚本提供。

1. 普通用户登录，进入“我的 → 救援记录”，打开已完成的演示任务，点击“生成业务复盘”。查看耗时、两项待办、事件和整理过程。
2. 使用另一个浏览器或无痕窗口登录志愿者，打开已参与的同一任务，确认 AED 归还。普通用户页面会提示复盘记录已变化，点击“更新复盘”。
3. 普通用户提交评价，再次更新复盘，检查两项待办均关闭。
4. 普通用户通过脉脉的「协同进展」或设备操作菜单的「查看协同记录」，查看故障设备的处理过程；在设备管理中恢复设备或上报其他设备故障，体验新的协同任务。
5. 首页打开「脉脉」，输入「隐私设置」或「推荐 AED 文章」，点击返回的真实入口。
6. 管理员登录，处理待审核 AED 和科普投稿；返回普通用户端检查审核结果。

已完成救援的直接链接：`http://localhost:5173/maian/#/pages/rescue/detail?id=<completedRescueId>`。志愿者打开相同链接时加上 `&mode=responder`。实际 ID 从启动输出或 `demo.json` 读取。

## 检查与恢复初始数据

环境运行后另开终端执行：

```bash
npm run test:preview
npm run test:agent
```

检查真实账号登录、角色权限、前端代理、救援参与权限、后台资源协同、助手入口与文章推荐，并通过取消记录执行复盘；保留已完成记录供用户第一次生成复盘。该检查可以重复运行，不会替用户归还设备或提交评价。

`test:agent` 使用独立自测账号和真实模型，检查指令修改设置、联系人增删、真实文件上传、文档投稿、体检文档入档与权限拦截。结束后清理该账号的文档、投稿、联系人与报告；不改动三个演示账号的资料。

需要重新演示初始待办时，先停止环境，再备份演示数据库并移除旧 ID 清单：

```bash
mv .cache/preview/preview.mv.db ".cache/preview/preview-backup-$(date +%Y%m%d-%H%M%S).mv.db"
rm .cache/preview/demo.json
npm run dev:preview -- --skip-build
```

仅重建演示数据库，Java、Maven 缓存和本地密码保留。测试和比赛服务器部署仍需使用 MySQL 8 执行完整迁移、配置 HTTPS、模型凭据及地图服务，并进行实库和真机联调。
