# 资源协同与全局执行助手

项目沿用 Spring Boot 3.5 / Spring AI 1.1.8，包含事件驱动的资源协同、救援复盘与全局执行助手。

## 资源协同

入口：**我的急救设备 → 设备操作菜单 → 协同记录**。设备操作菜单提供“报告设备故障”；已有救援关联的故障设备修复后，可选择“确认修复并恢复”。

设备停用、故障上报、重新启用、资料更新、审核通过、移动设备位置恢复时，在同一业务事务中写入协同任务。事务失败时设备变更和任务一起回滚。任务表独立保留设备名称和事件信息，设备删除后仍能查看历史。

后台协调器按以下工具检查事实并推进任务：

1. `inspectDevice`：读取当前状态、开放时段、有效期和位置新鲜度。
2. `inspectRescueImpact`：检查原设备与救援的当前关联及志愿者接单情况。
3. `findAlternatives`：查询最多三个替代候选的估算 ETA；此时不预留设备。
4. `coordinateResources`：在事务中重新检查条件，执行允许的资源调整。

开启模型时通过 Spring AI `@Tool` 调用工具；关闭模型、模型失败、调用超时或模型未完成工具执行时，使用同一套业务工具兜底。实际执行模式保留在接口结果中，页面按需展开真实工具过程。

### 执行边界

- 尚无志愿者接单且仍在原匹配时限内：释放失效关联，重新匹配候选；无资源时保留等待流程，继续由原调度器重试，不延长原截止时间。
- 已有人接单或设备仍待归还：保留原任务、预留与保管关系，产生需要人工核实的结果；不自动改变取用安排。
- 已接单、尚未取用的固定 AED 故障时，当前志愿者可在救援详情确认换机。系统保留该志愿者，重新预留可用固定 AED 或其本人携带的在线移动 AED，并通知求救者；固定设备换机后需重新确认到达取用点。
- 没有替代资源时，换机请求不改变原预留。当前志愿者确认原 AED 未取用且无法继续后，可结束本次调度；系统释放活动任务锁与设备预留，故障设备仍停用，求救者可点击“重新呼救”。这两个操作均校验原设备 ID，已取用设备不能通过这些入口解除保管关系。
- 设备故障后禁止确认取用。设备管理方确认修复后恢复原预留，相关人工核实记录随之更新。
- 故障设备取消占用或归还后仍保持停用，直到管理方主动确认启用。
- 资源恢复可用时，检查附近最多 20 个等待任务；实际匹配仍经过原有事务锁和资格校验。
- 原救援调度器独立检查尚未接单任务的设备可用性并重新匹配；模型调用使用独立线程池和调度器，不进入 SOS 请求链路。
- 实时调度器先移除失效设备但尚未找到替代资源时，协同记录仍保留待跟进提醒。后续正常调度匹配成功或等待救援结束后，记录自动更新结果。
- 已接单设备的故障记录在修复后关闭；先归还再修复、先提交修复事件再归还均可核对，不要求原预留关系仍然存在。归还后尚未修复的设备继续保留提醒。
- ETA 继续使用现有估算模型，候选预览不代表已经规划了道路路线。

任务和步骤写入 MySQL，通过页面每 3 秒刷新展示真实过程。救援状态调整沿用原 SSE 通知。执行中断的任务在租约到期后可恢复；执行操作按任务幂等，失败任务可由设备所有者重新检查。

救援详情中的协同记录使用独立轮询：救援进入终态后，仍继续读取尚未完成的协同结果和待归还设备的进展；全部处理完成后停止。请求失败会重试，页面隐藏或卸载时停止，重新显示时重新读取，避免旧请求覆盖新结果。

独立的结果跟进器默认每 5 秒核对最多 30 条待跟进记录，按上次检查时间轮转。跟进仅检查业务事实并更新协同记录，不调用模型、不重新分配救援，也不会反复追加相同的过程步骤。可通过 `app.agent.follow-up-initial-delay-ms`、`app.agent.follow-up-interval-ms` 调整运行间隔。

### 权限与数据

- 我的协同记录只返回本人登记设备产生的任务。
- 救援关联记录仅向求救者和已经接单的志愿者开放。
- 模型工具返回受控状态、候选数量和估算 ETA，不外发求救者身份、症状、联系方式或精确位置。
- 工具结果以外的模型自由文本不用于执行操作或证明业务成功；普通对话可以展示模型的自然回答。

## 脉安助手

入口：**业务页面悬浮的「脉脉」形象**。28个业务页面均支持就地打开助手，也可展开为完整页面。登录、法律说明、完整助手页不重复放置入口；呼救页保留专用操作；救援详情支持带当前救援上下文的助手入口。地图资源弹层、展开的地图抽屉和阈值编辑弹层显示时暂时隐藏形象。

就地面板采用最大320×360px的小浮窗，靠近形象定位，按可用空间缩小。没有背景遮罩或模糊，原页面仍可操作；长内容在窗内滚动，复杂办理可点击展开进入完整页面。

现场急救描述（如“有个人晕倒了，需要急救”）直接走站内急救流程，避免等待模型：请求真实定位，使用同一套调度资格与排序查询附近最多3个AED，展示位置、资源、估算取送时间及导航入口；用户一次确认后才创建呼救并由原调度器匹配。预览不预留设备，资源查询失败或无候选不阻止呼救。定位失败提供重试和地图选点，不要求手填经纬度，也不使用默认地图中心作为现场位置；位置超过60秒会刷新并要求重新确认。网页版直接请求浏览器GPS并转换为设备采用的GCJ-02坐标，无需地图SDK密钥；手动选点复用已有高德底图。地图初始中心仅用于浏览，用户点击并确认选点后才能作为现场位置。现场描述保留原文，不让模型猜测坐标、地址或医疗分级，非现场、条件及否定语句不进入急救快捷通道。定位和选点返回仍检查账号及会话归属。

形象支持触摸与鼠标拖动、边缘吸附并记住相对位置；在桌面 H5 中限制在手机预览区域。助手记录保留最近八轮，跨页面可继续查看，同一登录会话支持本机恢复；登录账号变化时清除记录并丢弃旧请求结果。请求进行中禁止重复提交，失败可重试，空结果明确提示。

助手支持直接办理业务，入口查找和已审核文章推荐仍保留。用户明确说「关闭科普更新」会调用真实设置接口；问「隐私设置在哪里」则返回入口。

「AI理解」在会话内默认开启，可随时关闭；开启时输入文字会发送至配置的模型服务。模型通过 `planTask` 选择允许的业务操作并提取明确参数，通过 `findAppPage`、`searchApprovedArticles` 查询入口或文章。模型未配置、失败或超时时使用保守的站内指令解析；内部保留实际执行模式供验证，聊天界面不展示规则兜底等实现标签，不伪造调用成功。

统一执行流程：识别指令 → 准备任务 → 检查参数与当前账号可见对象 → 必要时等待文件或补充信息 → 关键操作确认 → 调用原有业务接口 → 展示执行过程与真实结果。一个请求最多规划4个操作，依次执行；前一项未完成时后续项等待。

执行器只有固定操作与固定业务接口映射，不能执行任意URL、代码或模型生成的脚本。对象ID须来自当前账号真实可见的数据列表；业务后端继续检查角色、归属、救援状态和关联约束。删除、设备状态调整、呼救、审核、角色调整和报告入档须确认，模型传入参数不能跳过确认。网络中断导致新增结果不明时标记待核实，禁止一键重复提交。账号变化或清空会话后，停止后续步骤并丢弃旧响应。执行成功会通知当前业务页面刷新，设置同步过程不会反向提交旧值。

文档支持PDF、DOCX、UTF-8 TXT/MD/CSV，最多15MB；PDF最多100页、提取文字最多20万字，DOCX限制解压大小与条目数并禁用外部实体。PDF文字提取使用 [Apache PDFBox 3.0.8](https://pdfbox.apache.org/3.0/getting-started.html)。文档沿用媒体配额与私有下载令牌，保存后有业务引用，不会当成临时图片被回收。文件名仅作显示，服务器存储路径使用随机ID。

文档内容作为资料处理，不作为Agent指令；本版本不把整篇文档发送给指令模型。体检文档只提取原文中的机构、日期和指标，不猜测缺失信息，入档前允许补充与核对。图片识别仍依赖已配置的百度OCR及健康数据处理授权；未配置时明确报错并允许人工填写，不生成虚构结果。

每次模型请求最多调用8次工具，执行窗口12秒，限制并发和队列长度。第三方模型在规划阶段不直接持有数据库或会话权限；所有业务写入仍经当前登录账号的原有HTTP接口执行。

## 减少操作的全局办理

当前执行白名单包含63项操作。助手接收当前页面及明确选中的对象引用，列表序号以实际显示的列表为准；当前页面对象优先于其他页面的历史记录。所有对象仍须出现在本账号真实可操作的数据中，执行时继续使用原业务接口的权限和状态校验。多条记录有歧义时才要求选择，唯一候选自动选中；超出列表范围的序号直接提示，不替用户改选另一条记录。

前端执行代码按职责集中在 `src/utils/assistant/`：`catalog.ts` 统一定义操作名称、对象来源、表单、确认和创建策略；`operations.ts` 统一准备业务字段并调用现有接口；`files.ts` 处理上传、文档提取及报告指标解析。`assistantTasks.ts` 保留任务状态、账号校验、确认、取消和中断恢复；会话排队由 `useAssistantSession.ts` 管理。新增或调整操作时，先核对统一清单，避免维护两套分发表。

连续输入会合并到原任务，并保留已经填写的数据、已上传文件及后续排队步骤。例如“添加紧急联系人 → 我妈妈 → 手机号13800000000”完整后直接保存。确认页支持输入“确认”“取消”，不需要再调用模型；补充参数不能伪造确认。切换到不相关查询后，简短的“确认”不会执行之前隐藏的任务，用户可明确说“继续刚才的任务”。多步骤办理按顺序执行，已上传文件和已创建记录可以传给后续步骤；“刚才这份文档”可直接复用本人文件，避免再次选择和上传。

设备登记复用真实定位；定位失败可以地图选点，不让用户输入坐标。服务时间默认沿用登记页面的“全天”，确认前可修改；保存使用真实服务时段数组，不再提交空数组。硬件连接仍使用原蓝牙流程，助手不会仅写入一个连接标记就声称蓝牙已连接。

直接传文件时，包含明确报告日期及指标的文档会进入报告核对流程，普通资料保存为私有文档；在投稿或体检业务页面传文件会沿用对应用途。已有待上传任务优先接收文件。文档文字不参与指令规划，不能触发其中夹带的设置、删除或其他命令；识别检查单图片仍需真实OCR与授权。

提醒通过 `V23__assistant_reminders.sql` 持久保存，独立调度器按明确时间或真实审核状态推进，退出对话或重启服务不会丢失。前台显示待查看提醒数量，支持“十分钟后提醒我归还AED”“这台设备审核后提醒我”“查看我的提醒”“取消第一条提醒”。最多保留50条未结束提醒；这里只提供站内提醒，不发送短信或系统推送。任务补充只向指令模型发送本次新输入、允许补充的字段名称及最小页面信息，不重复发送旧字段值或完整文档。

### 任务恢复与语音输入

- 最近八轮任务、草稿、AI理解开关和已上传文件内容在本机保存，同一登录会话刷新后恢复。24小时无活动失效，清空或退出登录删除；不另存访问令牌。
- 恢复时沿用原任务执行器，重新读取当前账号可操作对象。旧确认不直接执行，急救与设备位置重新获取。已完成任务不重放，尚在执行且已发出写请求的任务标记“待核实”，不自动重复提交；请求前的只读阶段可重试。
- 连续任务共用前项结果继承逻辑，恢复后的后续任务仍使用前项创建的记录和上传文档，未完成前项不能跳过。
- H5在HTTPS或localhost且浏览器支持SpeechRecognition时显示麦克风，点击开始、再次点击结束，最终识别文字进入原有指令流程；已有草稿则追加文字供编辑。临时识别结果不会执行，原有危险操作确认仍生效。取消、关闭、隐藏页面或切换账号停止识别。识别失败可继续打字。
- 语音当前依赖浏览器识别服务，未配置Android原生识别SDK或小程序识别插件；不支持的端不显示不可用入口。参考[SpeechRecognition文档](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)。
- 输入栏和任务卡统一调用同一个文件选择与账号校验入口，删除重复校验；恢复提示在继续操作时自动消失。

### 自然对话与工具决策

模型可以直接回应问候、闲聊、感谢、能力说明与追问，不必调用搜索工具。有业务工具结果时，真实任务和真实卡片优先；普通文本不能成为已执行操作的回执，也不能新增虚构页面。

前端仅携带最近三轮普通文字对话作为语义上下文，不发送之前任务表单、上传文件内容或业务结果；清空与账号隔离继续生效。聊天界面保留可展开的业务过程，不显示内部执行模式标签。

复合指令整体交给模型规划，不能因识别到接单、提醒或救援操作而提前返回。模型不可用时，明确分隔且全部可识别的最多四项操作按原顺序执行；存在未识别、否定或条件语句时，保守解析不会只执行识别出的前半句。

## 救援复盘与待办 Agent

入口：已结束的**救援详情 → 救援复盘 → 整理救援记录**。该功能由用户主动请求，仅向本次求救者和已接单志愿者开放。处理使用独立后台任务与调度器，生成过程和结果持久化，重新打开页面可以继续查看。

工具协同过程：

1. `inspectTimeline`：核对最近最多 100 条真实救援事件，以及请求、响应、到场和完成确认的记录时间。
2. `inspectFollowUps`：读取 AED 保管状态与评价是否存在，识别待归还和待评价事项。
3. `findLearningMaterials`：检索最多 3 篇当前已审核、已发布的 AED 学习文章。
4. `assembleReview`：重新读取业务事实，生成结构化复盘、实际记录时段和业务待办。

页面保留实际事件与工具执行过程。未记录或时间顺序异常的时段显示“未记录”，估算 ETA 不作为实际耗时；不评价医疗效果。归还待办仅为志愿者定位已有确认按钮，评价待办仅为求救者定位评价表单。文章入口使用真实内容 ID，已下架的文章在读取复盘时过滤。

默认使用站内规则整理。用户在更多选项中打开“AI 协同整理”开关且服务端启用 AI 时，才通过 Spring AI 调用工具。模型只接收受控状态和数量，不接收事件原文、精确时间、位置、身份、症状、联系方式、评价分数或评语；模型自由文本不进入页面事实。模型失败或没有完成工具调用时，由相同业务服务兜底。

归还或评价记录变化后，旧复盘提示“救援记录有更新，请重新整理”，隐藏旧的操作入口，用户可点击“更新复盘”。同一救援的最新复盘重复请求会复用结果，生成中的任务也不会重复入队。后台任务使用租约和执行令牌，中断后可恢复，旧执行者不能覆盖新任务结果。页面仅在生成中或仍有待办时继续检查，隐藏后停止，重新显示时重新读取。

新增接口与迁移：

GET  /api/v1/rescue-reviews/{rescueCallId}

Flyway `V21__rescue_reviews.sql` 创建复盘及执行步骤表。后台调度可通过 `app.agent.review-initial-delay-ms` 和 `app.agent.review-interval-ms` 配置，默认 2 秒。

## 配置与验证

默认无需模型密钥即可验证规则协同及站内检索。启用 AI 工具调用沿用服务端配置：

```bash
export APP_AI_ENABLED=true
export OPENAI_API_KEY='your-model-key'
export OPENAI_MODEL=deepseek-chat
```

数据库由 Flyway `V19__resource_coordination.sql` 创建任务和步骤表，`V20__coordination_follow_up_index.sql` 为持续跟进查询添加索引。新增接口：

```text
POST /api/v1/emergency-devices/{id}/fault
POST /api/v1/rescue-calls/{id}/aed-replacement
POST /api/v1/rescue-calls/{id}/resource-failure
GET  /api/v1/coordination-tasks/mine
GET  /api/v1/coordination-tasks/rescue/{id}
POST /api/v1/coordination-tasks/{id}/retry
POST /api/v1/assistant
```

换机与结束故障调度接口仅向本任务的当前志愿者开放，请求体为 `{"expectedDeviceId":"原设备 UUID"}`；换机记录为 `AED_REPLACED` 事件，确认结束调度记录为 `SYSTEM_FAILED` 事件。
